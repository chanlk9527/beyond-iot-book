
# 3.3 设备生命周期：从激活到退役

上一节讨论了设备身份的来源。

我们知道，平台需要为每一台设备建立一个稳定的身份，使它能够被长期识别和管理。

但设备身份建立以后，并不意味着设备已经真正开始服务。

例如，晴川生产了一批智能灯。

这些灯可能已经提前登记到星云平台，但它们可能还在仓库中，没有卖给用户，也没有连接网络。

另一盏已经安装在用户家里的灯，则可能每天接受控制、上报状态，并产生运行数据。

它们都有设备身份，但处于完全不同的阶段。

因此，IoT 平台除了管理“设备是谁”，还需要管理：

> 设备现在处于什么状态，以及它经历过哪些变化。

这就是设备生命周期。

---

## 3.3.1 设备不是从“上线”开始存在

很多简单的 IoT 系统，会把设备理解成：

```
设备上线
    ↓
设备工作
    ↓
设备离线
```

但真实产品远比这个复杂。

一台智能灯从生产到用户使用，可能经历：

```
生产
 ↓
登记
 ↓
库存
 ↓
激活
 ↓
运行
 ↓
转移
 ↓
退役
```

其中：

生产阶段，平台可能只知道这台设备未来存在；

激活阶段，设备才真正进入用户服务；

运行阶段，设备持续产生数据和交互；

退役阶段，设备停止提供服务。

如果平台没有生命周期概念，就很难区分：

- 仓库里等待销售的设备；
- 用户正在使用的设备；
- 已经损坏的设备；
- 已经停止服务的设备。

这些设备在数据库里可能都只是“一条记录”，但业务含义完全不同。

---

## 3.3.2 激活建立设备与使用者之间的关系

在消费 IoT 中，激活通常是用户第一次真正使用设备的过程。

例如：

用户购买晴川智能灯。

打开 App。

扫描二维码。

按照提示完成配网。

之后，这盏灯出现在用户家庭中。

这个过程通常被称为设备激活。

激活前，平台知道：

> 有这样一台设备存在。

激活后，平台知道：

> 这台设备正在为某个用户或家庭提供服务。

因此，激活通常会伴随一些关系建立：

- 设备属于哪个家庭；
- 哪些用户可以控制；
- 使用哪些默认配置；
- 是否开始计算服务周期。

需要注意的是：

**激活不等于设备身份创建。**

一台设备可能在工厂阶段已经拥有平台身份，只是在用户购买以后才完成激活。

这也是为什么设备身份和设备使用关系需要分开设计。

---

## 3.3.3 生命周期状态和连接状态不是一回事

IoT 系统中一个常见误解是：

> 在线就是正常，离线就是故障。

实际上，这两个概念描述的是不同事情。

连接状态回答：

> 设备现在能不能和平台通信？

例如：

- 在线；
- 离线；
- 最近一次连接时间。

生命周期状态回答：

> 设备在业务上处于什么阶段？

例如：

- 未激活；
- 使用中；
- 暂停服务；
- 已退役。

两者可能出现不同组合。

例如：

一盏用户还没有安装的智能灯：

```
生命周期：
已登记，未激活

连接状态：
离线
```

这是正常情况。

而一盏正在使用中的智能灯：

```
生命周期：
运行中

连接状态：
离线
```

则可能需要进一步判断：

是网络暂时中断？

还是设备故障？

还是已经被用户断电？

因此，平台不能只通过连接状态判断设备是否可用。

---

## 3.3.4 设备生命周期中的常见变化

设备进入运行阶段以后，仍然会发生变化。

### 设备转移

例如：

用户把智能灯送给别人。

设备本身没有变化：

- 设备 ID 不变；
- 硬件不变；
- 历史记录仍然属于这台设备。

变化的是：

- 当前用户；
- 家庭归属；
- 控制权限。

因此，设备转移通常是关系变化，而不是重新创建设备。

---

### 恢复出厂

智能设备通常提供“恢复出厂设置”。

但恢复出厂并不意味着平台删除设备。

例如：

用户重新出售智能灯。

设备本地可能需要清除：

- Wi-Fi 信息；
- 家庭配置；
- 用户绑定。

但平台仍可能保留：

- 生产信息；
- 维修记录；
- 安全审计信息。

否则设备重新进入系统时，平台无法确认它是否还是原来的设备。

---

### 设备退役

任何设备最终都会退出服务。

例如：

- 用户主动删除设备；
- 产品停止支持；
- 硬件损坏无法维修。

退役并不一定意味着立即删除所有数据。

平台可能仍需要保留：

- 历史运行记录；
- 售后信息；
- 安全日志。

因此，“停止使用”和“从系统消失”是两个不同动作。

---

## 3.3.5 星云中的设备生命周期

在星云中，设备对象不会只有一个简单的状态字段。

一个设备通常需要同时记录多个维度：

```
Device

├── Identity
├── Product
├── Owner
├── Lifecycle State
├── Connection State
└── Runtime Data
```

例如，一盏智能灯可能是：

```
设备身份：
device_001

产品：
晴川智能调光灯

归属：
张三家庭

生命周期：
运行中

连接状态：
离线

最近状态：
亮度 50%
```

这些信息并不冲突。

它仍然属于张三家庭，也仍然是一台正常使用中的设备，只是当前暂时无法连接平台。

---

设备生命周期的意义，在于让平台理解：

> 设备不是一次连接产生的一条数据，而是一个长期存在、不断变化的业务对象。

身份解决“它是谁”。

生命周期解决“它现在处于什么阶段”。

连接解决“它现在是否能够通信”。

把这几个概念分开，平台才能支持设备从生产、销售、使用到退出的完整过程。
