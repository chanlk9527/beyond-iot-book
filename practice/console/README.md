# 多租户管理后台

独立的 Vue 3 + TypeScript 前端工程，采用 Vite、Pinia、Vue Router 与 Element Plus；与仓库根目录的书稿站点分别安装依赖、构建和部署。需要 Node.js 24。

已实现登录／退出、会话恢复、路由守卫、控制台概览、固定租户归属、成员资格验证失败提示，以及加载／空数据／网络错误状态。布局适配桌面与窄屏。页面读取真实接口，不附带自动启用的模拟账号、模拟数据或设备数量。

## 安装与启动

在本目录执行：

```powershell
npm.cmd ci
npm.cmd run dev
```

浏览器访问 `http://127.0.0.1:5173`。Windows 使用 `npm.cmd` 可以避免 PowerShell 误读被安全工具透明加密的 npm.ps1；其他系统可直接使用 `npm`。

先按 [后端说明](../backend/README.md) 启动 `management` profile，并显式创建初始账号。默认由 Vite 将 `/api/management` 代理至 `http://127.0.0.1:8080`，前端始终发起同源请求，无需开放后端 CORS。管理功能未开启或后端不可用时，页面会显示连接错误；普通账号必须在创建时绑定唯一租户，平台超级管理员独立初始化。

需要更改代理目标时，将 `.env.example` 复制为 `.env.local` 并调整 `API_PROXY_TARGET`，然后重启 Vite。该变量只在开发／预览服务器读取，不作为客户端配置打包；不在前端环境变量中保存密码、Cookie 或密钥。端口固定，已占用时显式报错，不自动漂移。

## 产品与设备管理

“产品与设备”入口为`/catalog`，普通账号直接进入`/me.tenantId`对应租户，平台超管进入全部租户及无租户数据范围，列表显示数据归属，详情可跨租户读取。不提供“我的租户”、租户切换器或范围选择页面。仅经过超管身份检查的平台产品设备读取接口查询全量；普通账号仍固定租户。平台入口创建产品仍为无租户归属，编辑和登记设备按资源实际归属提交。产品目录属于平台共享数据：所有租户读取同一份目录，仅平台超管可维护，删除检查全部租户及无租户产品引用，改名保留原 ID 和产品关联。列表、详情、修改和设备产品关联都由后端重复校验归属；租户观察者只能读。

产品支持搜索／分页、创建、基本信息及物模型JSON草稿编辑、暖奶器示例、草稿发布为不可变版本、历史版本查看与产品启停。发布前必须保存草稿，设备不会随最新模型版本自动升级。设备登记成功即启用，可使用凭证接入；启用不代表在线。设备支持搜索／分页、按同范围启用且发布的产品登记、详情、名称与生命周期修改，以及凭证轮换。

设备凭证可在详情中按权限查询或轮换，弹窗关闭／页面切换后清除当前显示值，不存浏览器存储。登记需要device:write、device:credential和用于选择产品的product:read；列表分别需要product:read或device:read；写入还受租户OWNER／ADMIN身份约束。其他权限点与API见后端device-manager/README.md。

本版设备登记凭证已接入MQTT 5认证，设备启用后使用后台显示的ClientId、用户名和密钥连接默认1883端口；页面不显示模拟在线数、设备上报或假控制结果。批量导入、归属迁移、设备通信／控制和 OTA 后续实现。

设备详情提供“设备状态”页签，查看上报值、期望值、差异及观测／接收时间；有设备写权限的管理员可设置或移除期望值。保存使用独立影子版本，冲突后先刷新再编辑；Redis 不可用时在该页签显示错误，不影响设备基础详情。期望值保存不表示已向设备下发或执行。

能力模型展示设备登记时绑定的已发布产品版本，包括属性类型与约束、操作输入和事件字段。若绑定版本为空而草稿已有能力，会明确提示并提供产品物模型入口；草稿和新发布版本不会自动覆盖已有设备绑定。

## RBAC 权限管理

导航“权限管理”分组下分别提供用户管理、角色管理、菜单管理三个页面。新建或编辑角色时按页面勾选可访问范围；菜单管理展示页面分组、功能说明、顺序、接口权限数量与已授权角色，也可从菜单查看角色授权。用户绑定一个或多个角色，页面访问取启用角色的并集。停用保留角色与绑定。

本阶段只配置页面级授权，不提供按钮权限编辑。已实现页面固定注册，包括租户管理、用户管理、角色管理、菜单管理、产品目录、产品管理和设备管理。控制台概览对已登录用户开放，详情页继承列表页权限。产品目录、产品管理和设备管理相互独立，设备登记所需产品查询能力不会自动开放产品页面。

`/me.permissions`中的`page:*`标识控制菜单、页签及路由守卫。直接输入无权限页面地址会返回概览，每次导航重新读取当前授权。新授权页面会由服务端配齐对应接口能力，原有接口校验、租户归属与成员身份约束继续生效。未返回的权限默认拒绝，不按用户名或platformAdmin标志在前端扩展权限。已有只读角色保留页面范围；仅保留原有页面或修改角色名称、状态不会自动增加写权限。

普通管理账号只能授予自身拥有的页面和接口能力，角色权限超过本人范围时不可编辑。自己的账号及平台超管账号继续受保护。平台超管身份独立，不能通过角色授予。角色编码创建后不修改；菜单来自实际路由，未提供自定义路由、外链或按钮权限配置。旧`permissions`角色接口继续兼容，新前端使用`menus`提交页面授权，两者不能同时提交。

## 租户管理

具有tenant:read权限的账号登录后，导航显示“平台管理 → 租户管理”，写入和成员操作按对应权限分别开放。可以分页搜索、新建、改名、启停租户；在详情中新建用户并固定绑定当前租户、调整OWNER／ADMIN／VIEWER角色、停用与恢复成员，并查看最近50条操作记录。停用保留数据，修改采用revision避免覆盖其他人的更新。

“新建用户”同时需要iam:user:write和tenant:member:write，停用租户不可新建。设置登录名、密码和租户角色后提交；登录名全平台唯一，不同租户不能复用同一账号。新账号的后台功能权限需在权限管理中另行分配角色，密码在关闭弹窗或离开页面时清除。

功能权限来自`/me.permissions`，不根据用户名或租户角色推断；服务端独立执行权限检查，未授权用户即使直接请求平台接口也无法访问。普通账号固定绑定唯一租户，平台超管独立。授权初始化见后端README。不会自动创建租户；已有普通用户创建和产品设备管理页面，公开注册与平台管理员维护尚未实现。

## 工程结构

```text
src/
├── api/management.ts         请求、CSRF、错误处理与请求取消
├── stores/session.ts         账号会话与固定所属租户
├── router/index.ts           懒加载路由与登录守卫
├── layouts/ConsoleLayout.vue 导航、所属租户显示与退出
├── components/               图标与统一空／错误状态
├── views/                    登录、概览、租户列表、详情和404
└── styles/main.css           主题与响应式布局
deploy/nginx.conf             静态部署与同源反向代理示例
```

账号身份只从 `/me` 恢复，认证由服务端 HttpOnly Session Cookie 承载；不在 localStorage 或 sessionStorage 保存账号、密码、Token 或租户权限。登录与退出前重新获取 CSRF token，登录表单使用 `application/x-www-form-urlencoded`。401清理本地状态并返回登录页，403按无权限展示，不自动重试写操作。

普通账号使用`/me.tenantId`直接定位业务范围，租户名称仅作为静态身份信息展示。旧租户列表／详情页面地址跳转至`/catalog`，不能用旧路径更改账号归属。平台维护保留`/platform/tenants`；退出清空用户和所属租户并取消在途请求，服务端每次重新验证成员及资源归属。

现阶段账号、租户成员、产品和设备管理可用；规则、告警、OTA等业务后续实现。

## 部署

将 `dist/` 部署到静态服务器，以站点根路径提供页面。使用 [Nginx示例](deploy/nginx.conf) 配置SPA路由回退，以及 `/api/management/` 到后端的反向代理；不要把API路径回退为index.html。按实际环境修改静态目录、域名、后端目标和HTTPS终止配置，示例尚未实测部署。

生产环境启用HTTPS，并在后端设置 `SESSION_COOKIE_SECURE=true`。保持页面与API同源，保留Cookie、CSRF与服务端授权；不要通过关闭安全校验解决代理问题。Vite的`API_PROXY_TARGET`不会改变生产静态站点的代理，生产代理由Nginx等部署设施配置。子路径托管需要同时调整Vite base、路由history base与反向代理，本版默认部署到根路径。

功能边界和模块约定见 [项目架构](../docs/architecture.md)。


产品目录的共享规则、品类 ID 与过滤语义见 [设备管理说明](../backend/platform-manager/device-manager/README.md#二级产品目录)。

### 菜单维护（平台超管）

在“权限管理 → 菜单管理”点击“新增菜单”或“编辑菜单”。先选择已开发注册的页面，路由自动带出，再填写菜单名称、分组、顺序、功能说明，勾选页面依赖的接口权限；可搜索权限名称/编码，或使用页面建议权限。所有现有页面已初始化为菜单，因此默认无需重复新增。

菜单定义和关联接口持久化到数据库。`/me.menus`返回当前用户可见的菜单，侧边栏与页面导航使用保存后的名称、分组和顺序；导航时重新读取配置。新页面仍需开发者先实现并注册组件、路由与后端能力，再从维护入口配置菜单。

保存接口关联前展示受影响角色及新增/移除项数。接口变更同步到所有绑定角色（包括停用角色），保留其他已授权页面需要的共享权限；只修改名称等展示信息不会扩大旧只读角色能力。角色版本随授权变化递增，旧编辑请求返回冲突。菜单仅平台超管可维护，普通管理员继续在角色管理中勾选页面。删除菜单前必须解除所有角色绑定，菜单维护入口自身不可删除；删除后可从已注册页面重新创建。
