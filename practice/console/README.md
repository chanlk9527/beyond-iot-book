# 多租户管理后台

独立的 Vue 3 + TypeScript 前端工程，采用 Vite、Pinia、Vue Router 与 Element Plus；与仓库根目录的书稿站点分别安装依赖、构建和部署。需要 Node.js 24。

已实现登录／退出、会话恢复、路由守卫、控制台概览、固定租户归属、成员资格验证失败提示，以及加载／空数据／网络错误状态。布局适配桌面与窄屏。页面读取真实接口，不附带自动启用的模拟账号、模拟数据或设备数量。

## 安装与启动

在本目录执行：

```powershell
npm.cmd ci
npm.cmd run dev
```

浏览器访问 `http://127.0.0.1:5173`。Windows 使用 `npm.cmd` 可以避免 PowerShell 误读被安全工具透明加密的 npm.ps1；其他系统可直接使用 `npm`。

更新代码后若新菜单进入“页面不存在”，先刷新浏览器，确保加载最新路由。开发者中心为 `/developer`，平台超管的开放平台管理和设备接入分别为 `/platform/openapi`、`/platform/access-nodes`。依赖锁文件变更后执行 `npm ci` 并重启 Vite；macOS 快捷命令为 `./practice/manage.sh restart --frontend-only --install`（仓库根目录执行）。使用 `npm run preview` 或 Nginx 时，必须先执行 `npm run build`，旧 `dist` 不会随源码更新。开发服务器仅额外允许读取 `practice/docs` 中的共享开发文档。

先按 [后端说明](../backend/README.md) 启动 `management` profile，并显式创建初始账号。默认由 Vite 将 `/api/management` 代理至 `http://127.0.0.1:8080`，前端始终发起同源请求，无需开放后端 CORS。管理功能未开启或后端不可用时，页面会显示连接错误；普通账号必须在创建时绑定唯一租户，平台超级管理员独立初始化。

需要更改代理目标时，将 `.env.example` 复制为 `.env.local` 并调整 `API_PROXY_TARGET`，然后重启 Vite。该变量只在开发／预览服务器读取，不作为客户端配置打包；不在前端环境变量中保存密码、Cookie 或密钥。端口固定，已占用时显式报错，不自动漂移。

## 产品与设备管理

“产品与设备”入口为`/catalog`，普通账号直接进入`/me.tenantId`对应租户，平台超管进入全部租户及无租户数据范围，列表显示数据归属，详情可跨租户读取。不提供“我的租户”、租户切换器或范围选择页面。仅经过超管身份检查的平台产品设备读取接口查询全量；普通账号仍固定租户。平台入口创建产品仍为无租户归属，编辑和登记设备按资源实际归属提交。产品目录属于平台共享数据：所有租户读取同一份目录，仅平台超管可维护，删除检查全部租户及无租户产品引用，改名保留原 ID 和产品关联。列表、详情、修改和设备产品关联都由后端重复校验归属；租户观察者只能读。

产品支持搜索／分页、创建、基本信息及物模型可视化／JSON草稿编辑、暖奶器示例、草稿发布为不可变版本、历史版本查看与产品启停。发布前必须保存草稿，设备不会随最新模型版本自动升级。设备登记成功即启用，可使用凭证接入；启用不代表在线。设备支持搜索／分页、按同范围启用且发布的产品登记、详情、名称与生命周期修改，以及凭证轮换。

物模型编辑器支持属性、功能、事件的名称与说明、枚举选项、数组元素／项数及数值单位，定义与边界见 [物模型说明](../docs/thing-model.md)。设备详情的“网关拓扑”支持绑定与解绑单层网关／子设备关系；子设备通过网关代理接入，不能直接使用自身凭证连接 MQTT，详见 [网关接入](../docs/mqtt-protocol.md)。

设备凭证可在详情中按权限查询或轮换，弹窗关闭／页面切换后清除当前显示值，不存浏览器存储。登记需要device:write、device:credential和用于选择产品的product:read；列表分别需要product:read或device:read；写入还受租户OWNER／ADMIN身份约束。其他权限点与API见后端device-manager/README.md。

本版设备登记凭证已接入MQTT 5认证，设备启用后使用后台显示的ClientId、用户名和密钥连接默认1883端口；页面通过实时通知与HTTP快照展示在线状态和上报属性，已接入属性写入、操作调用与结果查询。批量导入、归属迁移和OTA仍待实现；跨节点控制需后端显式启用cluster-commands。

设备详情提供“设备状态”页签，查看上报值、期望值、差异及观测／接收时间；有设备写权限的管理员可设置或移除期望值。保存使用独立影子版本，冲突后先刷新再编辑；Redis 不可用时在该页签显示错误，不影响设备基础详情。单独保存期望值不触发下发；“保存并下发”分别呈现影子保存与命令下发结果，两步不具备原子性，命令受理也不表示设备执行完成。

能力模型展示设备登记时绑定的已发布产品版本，包括属性类型与约束、操作输入和事件字段。若绑定版本为空而草稿已有能力，会明确提示并提供产品物模型入口；草稿和新发布版本不会自动覆盖已有设备绑定。

### 生产与交付

新增 `/catalog/platform/production` 和 `/catalog/tenants/{tenantId}/production` 页面，沿用目录导航和租户范围，页面权限为 `page:production`，已有普通角色需另行授权。支持新建批次、生成1～50台设备、显式下载凭证JSON、逐台登记人工烧录／测试、整批放行及交付，操作记录支持分页。交付只登记对象和单号，不改变设备归属或App绑定。

只有当前凭证版本已烧录且测试合格的整批设备才能放行／交付；返工需重新放行。凭证导出需额外权限和显式勾选确认，页面不展示或缓存整批密钥。硬件测试与烧录仍由现场人员执行。后端规则与限制见[生产与交付管理](../backend/platform-manager/device-manager/README.md#生产与交付管理)。

### 数据策略与设备历史

产品详情的“数据策略”页签维护属性、事件各自的产品默认及单项覆盖，支持恢复继承。策略独立于物模型定义保存到服务端，使用自己的 revision；不随物模型保存或发布。物模型属性与事件列表提供同一策略抽屉和“保存数据策略”入口。新增标识先保存定义，再配置策略。

页面按后端存储能力开放选项。首版支持最新属性值开关、每次上报记录、按天保留及不存历史；严格条数保留、变化采样、间隔采样和小时聚合尚未实现，界面禁用且后端拒绝保存。历史默认关闭，需部署 TDengine 后显式开启采集。只读用户可查看；写入沿用产品写权限及租户管理员校验。旧浏览器本地预览不会自动应用为真实策略。

属性单项上报、部分上报和全量上报统一按实际出现的属性写历史，不补齐未上报值。最新值开关作用于后续影子上报更新，不删除已有快照。事件连同所有字段作为完整记录保存，与同名属性分开；关闭事件历史不关闭实时事件处理。

设备详情的“设备历史”页签可按属性／事件、标识及时间范围查询真实历史，并使用游标翻页；支持输入旧模型标识。JSON 原值以文本展示，避免浏览器浮点转换损失精度。服务未启用或不可用时显示明确错误。部署、接口、清理与故障恢复边界见 [历史存储组件](../backend/platform-components/storage-component/README.md)。

## RBAC 权限管理

导航“权限管理”分组下分别提供用户管理、角色管理、菜单管理三个页面。新建或编辑角色时按页面勾选可访问范围；菜单管理展示页面分组、功能说明、顺序、接口权限数量与已授权角色，也可从菜单查看角色授权。用户绑定一个或多个角色，页面访问取启用角色的并集。停用保留角色与绑定。

本阶段只配置页面级授权，不提供按钮权限编辑。已实现页面固定注册，包括租户管理、用户管理、角色管理、菜单管理、产品目录、产品管理和设备管理。控制台概览对已登录用户开放，详情页继承列表页权限。产品目录、产品管理和设备管理相互独立，设备登记所需产品查询能力不会自动开放产品页面。

`/me.permissions`中的`page:*`标识控制菜单、页签及路由守卫。直接输入无权限页面地址会返回概览，每次导航重新读取当前授权。新授权页面会由服务端配齐对应接口能力，原有接口校验、租户归属与成员身份约束继续生效。未返回的权限默认拒绝，不按用户名或platformAdmin标志在前端扩展权限。已有只读角色保留页面范围；仅保留原有页面或修改角色名称、状态不会自动增加写权限。

普通管理账号只能授予自身拥有的页面和接口能力，角色权限超过本人范围时不可编辑。自己的账号及平台超管账号继续受保护。平台超管身份独立，不能通过角色授予。角色编码创建后不修改；菜单来自实际路由，未提供自定义路由、外链或按钮权限配置。旧`permissions`角色接口继续兼容，新前端使用`menus`提交页面授权，两者不能同时提交。

## 租户管理

具有tenant:read权限的账号登录后，导航显示“平台管理 → 租户管理”，写入和成员操作按对应权限分别开放。可以分页搜索、新建、改名、启停租户；在详情中新建用户并固定绑定当前租户、调整OWNER／ADMIN／VIEWER角色、停用与恢复成员，并查看最近50条操作记录。停用保留数据，修改采用revision避免覆盖其他人的更新。

“新建用户”同时需要iam:user:write和tenant:member:write，停用租户不可新建。设置登录名、密码和租户角色后提交；登录名全平台唯一，不同租户不能复用同一账号。新账号的后台功能权限需在权限管理中另行分配角色，密码在关闭弹窗或离开页面时清除。

功能权限来自`/me.permissions`，不根据用户名或租户角色推断；服务端独立执行权限检查，未授权用户即使直接请求平台接口也无法访问。普通账号固定绑定唯一租户，平台超管独立。授权初始化见后端README。不会自动创建租户；已有普通用户创建和产品设备管理页面，公开注册与平台管理员维护尚未实现。

## 工程结构

```text
src/
├── api/                      管理、目录、影子、历史、接入与 EventBus 请求
├── stores/session.ts         账号会话与固定所属租户
├── router/index.ts           懒加载路由与登录守卫
├── layouts/                  管理控制台与开发者门户布局
├── components/               物模型编辑、设备控制、影子、历史、拓扑及公共组件
├── views/                    管理、产品设备、生产、运维及开发者页面
├── developer/                公开资料清单、链接映射与 Markdown 渲染
├── realtime/                 实时订阅、重连与快照刷新
├── media/                    WebRTC 播放
└── styles/main.css           主题与响应式布局
deploy/nginx.conf             静态部署与同源反向代理示例
```

账号身份只从 `/me` 恢复，认证由服务端 HttpOnly Session Cookie 承载；不在 localStorage 或 sessionStorage 保存账号、密码、Token 或租户权限。登录与退出前重新获取 CSRF token，登录表单使用 `application/x-www-form-urlencoded`。401清理本地状态并返回登录页，403按无权限展示，不自动重试写操作。

普通账号使用`/me.tenantId`直接定位业务范围，租户名称仅作为静态身份信息展示。旧租户列表／详情页面地址跳转至`/catalog`，不能用旧路径更改账号归属。平台维护保留`/platform/tenants`；退出清空用户和所属租户并取消在途请求，服务端每次重新验证成员及资源归属。

现阶段账号、租户成员、产品和设备管理可用；规则、告警、OTA等业务后续实现。

## 部署

将 `dist/` 部署到静态服务器，以站点根路径提供页面。使用 [Nginx示例](deploy/nginx.conf) 配置SPA路由回退，以及 `/api/management/` 到后端的反向代理；不要把API路径回退为index.html。按实际环境修改静态目录、域名、后端目标和HTTPS终止配置，示例尚未实测部署。

生产环境启用HTTPS，并在后端设置 `SESSION_COOKIE_SECURE=true`。保持页面与API同源，保留Cookie、CSRF与服务端授权；不要通过关闭安全校验解决代理问题。Vite的`API_PROXY_TARGET`不会改变生产静态站点的代理，生产代理由Nginx等部署设施配置。子路径托管需要同时调整Vite base、路由history base与反向代理，本版默认部署到根路径。

功能边界和模块约定见 [项目架构](../docs/architecture.md)。


产品目录的共享规则、品类 ID 与过滤语义见 [设备管理说明](../backend/platform-manager/device-manager/README.md#二级产品目录)。

### 菜单维护（平台超管）

在“权限管理 → 菜单管理”点击“新增菜单”或“编辑菜单”。先选择已开发注册的页面，路由自动带出，再填写菜单名称、分组、顺序、功能说明，勾选页面依赖的接口权限；可搜索权限名称/编码，或使用页面建议权限。所有现有页面已初始化为菜单，因此默认无需重复新增。

菜单定义和关联接口持久化到数据库。`/me.menus`返回当前用户可见的菜单，侧边栏与页面导航使用保存后的名称、分组和顺序；导航时重新读取配置。新页面仍需开发者先实现并注册组件、路由与后端能力，再从维护入口配置菜单。

保存接口关联前展示受影响角色及新增/移除项数。接口变更同步到所有绑定角色（包括停用角色），保留其他已授权页面需要的共享权限；只修改名称等展示信息不会扩大旧只读角色能力。角色版本随授权变化递增，旧编辑请求返回冲突。菜单仅平台超管可维护，普通管理员继续在角色管理中勾选页面。删除菜单前必须解除所有角色绑定，菜单维护入口自身不可删除；删除后可从已注册页面重新创建。

## 设备接入面板（平台超管）

“接入运维 → 设备接入”的路径为 `/platform/access-nodes`。默认展示当前进程；后端显式启用 cluster profile 后展示共享节点目录。数据包括监听状态、认证设备在线会话数、网络连接数／配置上限、上行处理成功及拒绝累计数；节点详情展示实例标识、进程启动与运行时间、监听地址和端口、工作线程与队列占用。

页面默认每 5 秒刷新，可关闭自动刷新或手动刷新；页面隐藏时暂停轮询，离开时取消请求。刷新失败保留上次采样并显示错误及采样时间；MQTT 未启用时展示未启用和不可用指标。单节点模式只观察当前进程；共享目录模式展示各节点的生命周期和最后心跳，在线设备总数取有效会话归属去重统计。节点失联或展示覆盖不完整时标记异常，缺失的连接与消息汇总不当作精确总量。在线设备按认证会话计数，连接包含认证中的连接；上行处理成功不等于业务已持久化，累计指标随网关实例重建重置。

这是平台超管专用的固定运维入口，不通过普通角色页面授权开放。路由和后端接口分别校验身份。面板当前仅开放观察，节点注册、共享指标及后端排空／恢复接入 API 已交付；自动扩缩容、面板运维按钮及完整业务集群仍未完成，规划统一维护在 [架构约定](../docs/architecture.md#设备接入控制面板)。
## 事件总线面板（平台超管）

`/platform/eventbus` 提供 Dubbo 节点、订阅、积压和运行采样的只读观察；Local／Kafka 明确显示观测未提供。未采集到的指标显示未知，不能按零流量解释。仅平台超管可访问，详细口径及限制见 [EventBus](../backend/EVENTBUS.md#只读管理面板)。

## 开发者门户

现有前端中增加独立布局的开发者入口，与管理控制台共享后端认证和租户权限。

| 路径 | 用途 | 访问要求 |
| --- | --- | --- |
| `/developer` | 首页与接入路径 | 无需登录 |
| `/developer/docs/:slug?` | 文档导航、全文搜索、页内目录 | 无需登录 |
| `/developer/examples` | OpenAPI 定义、PowerShell 示例下载 | 无需登录 |
| `/developer/apps` | 我的应用 | 有效租户 OWNER / ADMIN |
| `/platform/openapi` | 应用审核与启停 | 平台超管 |

公开文档不请求管理接口，不依赖管理端连接成功。应用页沿用登录校验；匿名访问会跳转登录，并在登录成功后返回应用页。平台超管访问应用页会进入平台审核页。

文档以 `practice/docs/` 中的 Markdown 为唯一来源，由 `src/developer/resources.ts` 显式选择公开资料并在构建时导入。修改文档后需重新构建前端；不会自动公开全部仓库文件。内部实现说明的链接不在公开清单中时只显示文字。

Markdown 渲染关闭原始 HTML 和远程图片，公开目录只映射已登记的文档和下载文件。新增资料时同步维护目录、相对链接、测试和部署产物。部署仍需将 `/developer/**` 等前端路由回退到 `index.html`，API 路径继续转发后端。

后续可将 `/developer` 布局迁移为独立前端或域名，当前没有引入额外账号体系。在线 API 执行、消息调试和 SDK 下载尚未提供。

## 设备模拟（MQTT over WebSocket）

设备详情的“设备模拟”页签运行浏览器 MQTT.js 客户端，使用当前设备凭证和绑定模型，经真实 MQTT 5 接入链路上报属性、事件并处理下行。入口要求设备写入、凭证权限及范围写权限；设备与产品必须启用，暂不支持子设备直接模拟。

勾选使用设备身份的说明后点击连接。支持部分属性、1～3600 秒定时上报、事件必填／选填字段，以及属性读写和操作的手动成功／失败应答。自动模拟成功应答默认关闭；操作应答不推断硬件行为，属性写入成功会更新模拟值并上报可读属性。切换设备详情内的页签保留连接，离开详情、权限失效或凭证版本变化时断开；连接失败不自动重连，避免与真实设备争抢同一身份。上报会影响真实影子及按策略开启的历史，建议使用专用测试设备。

连接地址固定为当前站点 `/mqtt`，密钥不放入 URL、日志或浏览器存储，仅在点击连接时从现有凭证接口读取。开发与预览代理默认转发至 `http://127.0.0.1:8084`，可通过 console 的 `.env.local` 设置 `MQTT_WS_PROXY_TARGET`，改动后重启 Vite。后端重新构建并启动后默认提供 `8084/mqtt`；集群第二接入节点为 `8085/mqtt`。示例 Nginx 已包含 `/mqtt` 升级代理，HTTPS 站点由 Nginx 终止 TLS 后转发到内网监听，浏览器使用 WSS。

时间线保留最近 200 条连接、收发与 PUBACK 记录，可展开原始报文。PUBACK 成功只表示接入接收，不等于历史持久化或设备执行成功。下行校验模型版本、有效期及物模型约束；最近 256 条应答与命令结果仅在本次模拟会话内去重，不提供跨刷新持久化。
### 大物模型的设备控制

设备详情的“设备控制”将属性写入和操作调用分开，左侧按名称、标识、说明搜索能力，每页 8 项。属性仅展示可写项，可逐项选择或“选中本页”；右侧只编辑已选属性，并独立分页。分页和搜索不会取消其他页的选择，发送时包含全部已选项，移除与清空选择会从请求中排除对应属性。

操作按当前绑定模型展示说明、必填／选填和本次提交数量。参数较多时支持搜索及每页 8 项分页，所有页的必填和勾选参数均会提交；未勾选选填参数不会发送。切换操作或控制类型时保留各自草稿，离开设备控制后清除，不写入浏览器存储。可展开 JSON 核对完整请求，失败后保留输入。发送区位于编辑区底部，等待回执时禁用重复发送，仍可搜索和浏览能力；最近一次结果标注原请求，避免与当前浏览的操作混淆。
模拟器将属性上报、事件上报、下行处理和消息时间线拆成独立工作区，顶部导航显示下行待处理数量；其他工作区收到下行时展示“立即处理”提示，不自动抢走正在编辑的表单。切换工作区保留连接、表单值与定时任务。属性和事件参数支持搜索及每页 8 项分页，区域内滚动；搜索、分页不影响全量已选属性或所有必填／已勾选事件参数的提交。属性支持选中／取消本页，导航持续标记定时上报运行状态。
### 统一设备调试工作台

设备详情将原“设备控制”和“设备模拟”合并为“设备调试”。平台端保持能力搜索、参数编辑和命令结果；具有设备写入和凭证权限的用户可以打开右侧模拟设备端，确认后连接真实 MQTT over WebSocket。默认展示下行处理，自动／手动应答模式始终可见，也可切换到属性、事件和消息时间线。平台提交命令后展开已打开的模拟面板，并以 messageId 定位本次下行；不会自动读取凭证或连接设备。

收起模拟面板、切换设备详情页签时保留同一个模拟会话与平台表单、结果查询；离开设备详情时统一清理，模拟权限失效时销毁模拟器。无凭证权限的用户继续按既有权限使用平台控制。宽屏并排展示，窄屏在平台控制下方展示可收起的模拟设备面板。旧章节中的控制／模拟页签入口统一由本工作台替代。
下行处理提供应答 JSON 编辑器，原始下行命令折叠只读展示。可填入成功／失败模板，编辑 result.code、result.message 和 data 后显式发送；replyTo、消息 ID 和应答方法由系统关联生成。属性返回清单必须与请求一致，值按绑定物模型校验；失败属性应答 data 为空；操作回执保留原 commandId，并保持 SUCCESS/SUCCEEDED 或非 SUCCESS/FAILED 一致。属性写入的编辑后实际值会更新模拟状态并上报。模板预览不执行操作、不锁定结果，校验或发送失败保留输入；传输结果未知时，已生成回执只允许原内容重试。原“模拟成功／失败”快捷按钮仍直接发送默认模板，明确不使用编辑内容。
