# 设备开发与接入

## 准备产品和设备

在管理端创建产品，定义属性、事件和操作，并发布物模型版本。登记设备时选择已发布版本，平台会生成设备身份和独立凭证。

设备身份用于区分设备，凭证用于认证。App ID 和应用密钥属于外部服务端，不能替代设备凭证。

## 连接和消息

当前默认设备协议使用 MQTT 5。设备连接、Topic、消息信封、属性上报、操作回复和错误格式见 [MQTT 默认协议](../mqtt-protocol.md)。固件应以该文档的实际支持范围为准。

```text
登记设备 → 保存凭证 → MQTT 认证 → 建立连接
→ 上报属性 / 事件 → 接收并处理命令 → 返回结果
```

设备启用只表示允许接入，不代表已经在线；平台受理命令也不代表设备执行成功。设备需要正确关联请求和回复，处理重复、超时与重连。

## 联调检查

- 设备生命周期为 ACTIVE，产品和租户均已启用。
- ClientId、用户名和设备 ID 使用平台约定，密码使用当前设备密钥。
- Topic 和消息中的设备、产品、租户信息一致。
- 上报字段匹配设备绑定的已发布物模型版本。
- 轮换凭证后更新设备配置，旧凭证不能继续连接。

本地默认 MQTT 地址为 `127.0.0.1:1883`。该地址只是开发配置；公网接入的地址和 TLS 方案由部署方提供，不能把本地明文配置直接当作公网安全方案。

## 与应用开发配合

设备接入解决“设备怎样与平台通信”；应用开发解决“外部服务怎样经过授权访问平台”。应用侧从 [OpenAPI 接入指南](../openapi/README.md) 开始，两条链路在平台的设备资源和权限处衔接。
