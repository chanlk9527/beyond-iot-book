# 规则引擎设计与实施记录

依据：[产品规划](rule-engine.md)、[架构约定](architecture.md#规则与集成边界)。2026-11-03 用户确认沿 JetLinks 的节点模型与执行器扩展方向实施，按阶段交付，不逐项照搬。

## 设计选择

保留 RuleModel / RuleNode / RuleLink、RuleData、ExecutionContext、TaskExecutorProvider / TaskExecutor。业务配置与运行模型分开：后续场景和流转分别转换成统一模型。采用组件层 JDK 21 实现，不引入 Reactor、Spring 或设备管理依赖；由 bootstrap 装配。

考虑过固定流水线（简单但难以平滑支持分支）、完整通用编排器（首版成本过高），选择通用图模型配合受限本地运行时。首阶段有一个入口，允许分支、禁止循环和合流；一个节点每次产生零或一个输出。复杂合流、多条输出和持久等待以后扩展。

计算层返回结果，不承担事务和外部发送。后续动作节点生成持久动作意图，由 rule-manager 将运行结果与待办原子提交；integration-manager、notification-manager、device-manager 各自执行。当前执行器 SPI 不提供可靠副作用保证。

## 第一阶段契约

- RuleModel 带规则 ID、版本、入口、节点和连线；ExecutionContext 带租户、运行 ID、事件 ID、规则版本与当前节点。
- 配置和数据仅支持 JSON 值，递归防御复制。租户来自可信调用方，不从 payload 取值；组件不替代授权校验。
- 所有图和执行器配置先校验，再创建执行器。拒绝重复节点/边、悬空边、不可达节点、循环、合流和未知执行器。
- 连线支持单字段结构化比较，缺失字段不命中；数字按数值比较，不做字符串到数字的隐式转换。AND/OR、时间条件后续补充。
- 本地执行顺序确定，兄弟分支独立；执行器异常标记当前节点失败，不执行其后继，但继续其他分支。异常对象不直接进入结果，避免泄露凭证。无输出为 FILTERED。
- 执行器按每次运行创建，不在不同运行间共享实例。首阶段同步计算，不提供任务调度、重试、取消、超时或资源隔离；不得接入生产外部 IO。
- 全图配置校验通过后，预先创建所有节点执行器，包括不会命中的分支。工厂抛异常或返回 null 属于启动失败，整体抛出，任何节点均不执行；只有执行阶段异常按分支隔离。
- RuleData 是输入快照；RunResult 提供各已访问节点的状态及输出，未访问节点可由模型与记录差集识别。
